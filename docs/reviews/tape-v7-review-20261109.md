**一、必须修复：字幕讲的动作与实际动作不一致**

问题ID：`EP03-V7-ACTION-ALIGNMENT-001`；P1；新发现，未执行影片修复，修复轮数0。下列时间来自实际冻结字幕；动作来自同版逐帧pose，明确区分字幕对应和未完成的语音词级听审。

| 时间 | 字幕 | 实际动作/状态 | 影响 |
| --- | --- | --- | --- |
| 1.5625—2.6018秒 | 再让它回去 | 尺带伸出量约5.07→16.22mm，仍向外拉；真正回收约4.8秒后才开始 | 开场第一次演示就与文字方向相反 |
| 82.7107—84.778秒 | 压脚压住尺带就能保持 | 尺带约2.87→20mm，锁止量0→0.387；大部分区间尚未锁住 | 说“保持”时画面还在拉出、随后才加锁 |
| 84.778—85.7177秒 | 解除锁止 | 锁止量约0.435→1，实际上完成加锁 | 关键概念被反向演示 |
| 85.7177—87.0333秒 | 卷簧释放能量 | 尺带始终20mm，先锁住、后开始退锁，尚未收回 | 没有显示本句宣称的回收变化 |
| 87.0333—88.1609秒 | 把尺带收回 | 尺带仍始终20mm；回收在约88.23秒之后才开始变化 | 本句讲完才发生动作，动作落在最后总结句 |

`lock=0`表示退开，`lock=1`表示压脚名义接触。不是由指标猜测：真实编码画面的主体区域在85.5和86.5秒两次采样的像素均差为0；86.5秒关键帧写着“卷簧释放能量”，实际仍为闭壳、尺带伸出状态。像素比较只证实所取两帧和区域，不扩成连续全片结论。

**根因：** `film_motion.configuration()`用整个语音段的百分比安排拉出、加锁、退锁、回收；字幕则按段内文字权重估时。原检查验证长度、端点连续和机械名义状态，没有逐句核对动作语义。两条时间轴各自合法，合起来却是错的。

**最小修复：** 保留锁定旁白、整体风格和已核实源机构；在独占新版本中按对应动作句安排开头与结尾的事件时间，不靠延长时长处理。先实测/听审相关短句边界，再分别对齐“拉出—回收”和“拉出—锁住—解除—回收”；同步字幕与拟音，复查邻段。不能只把字幕往后挪来掩盖与语音的错位。

**复验标准：** “回去/收回”对应区间伸出量确实下降；“解除锁止”时lock下降；“压住保持”对应保持状态；事件先后正确，动作开始/结束与实际语音/字幕匹配。受影响局部先通过，再组装成片并重查最终媒体。

**二、必须修复：机构虽然连上，关键连接仍没展示清楚**

沿用关联问题ID：`EP03-V7-CONTROL-001`，补充视觉证据；P1。既有外控几何修复轮数1保留，不抹掉其已完成的源结构修正，也不把本次补查当成修复计数重置。

V7已经有外部按钮、贯穿连片、内侧舌片、压脚的实体链；所列有限姿态的连接/无壳壁干涉证据保留。但“实体存在并连接”和“观众看见它怎样传力”是两项检查。

本次冻结场景射线结果：

| 秒 | 连片 web38 可直接看见的采样面中心 | 压脚 shoe60 可直接看见的采样面中心 |
| --- | --- | --- |
| 26 | 0 / 108 | 29 / 108 |
| 51 | 0 / 108 | 31 / 108 |
| 54.8 | 0 / 108 | 11 / 108 |
| 70.5 | 0 / 108 | 34 / 108 |

这是有限表面采样，不是面积百分比，不证明整件在所有帧完全不可见。四个实际姿态均未见连片采样点，主要被壳边、导向件和舌片遮住；与51秒实际关键帧的可读性问题相互印证。压脚完整投影框在51秒约48×97原生像素，真正可见的工作面更少；54.8秒锁住时压脚仅11个采样面中心可见。

画面上方写了“外滑钮→连片→内压脚”，但标注没有实际指向连片或夹持界面。51秒虽放大了机构，画面重心仍是卷簧/尺带圈，左侧卷层还被裁切。文字列出链条，不能替代把链条展示出来。

**根因：** 前一轮评审围绕“零件是否连成一体、是否穿过开口、是否碰撞”；没有要求相机必须看见关键连片及制动接触。局部8秒样片仅覆盖接近压脚阶段，也没证明最终压住与释放的可读性。

**最小修复：** 优先保留已修正确的源几何和成熟画面语言，仅在锁止/释放局部调整观察方向或明确标注教学剖示，展示完整外壳上的操作位置，再沿同一参照看到连片到压脚。需要一个能同时区分压脚、尺带、支承面的接触视角，随后在相同参照展示退开间隙。不得以隐藏错误几何代替修复，也不恢复已耗尽的尺钩重建策略。

**复验标准：** 把button36、web38、tongue34、shoe60及夹持界面列为实际前检对象，不能只测整个机构或可见按钮；规定动作窗口内检查真实pose。实际小样不读制作解释时能复述“外钮经过哪件带动压脚、压在哪里、退开后什么改变”。

**三、应改进：时间花在重复解释，关键证据仍不够突出**

P2建议，不把它作为已确认平台留存原因：

- 56.07—68.09秒约12秒，连续讲“尺带停住、卷簧未恢复、仍有趋势、不能滑动、能量没用掉”。动作数据为伸出60mm且lock=1，主要是相机移动。保持状态本身有解释价值，但同一关系被多句重复，缺少“仍储能”与解除后变化的直观对照。
- 20.64—33.24秒讲固定端/连接端时，26秒关键帧的青色接头很小，文字没有实际引线；应先让观众定位接头，再给关系说明，避免需要猜指哪一端。
- 顶部术语标注较小且灰/青色对比弱；字幕规格虽合格，信息层级仍需在手机尺寸审查。尚未做平台UI遮挡实测，不能称“移动端可读性已经通过”。

保留核心知识、减少重复句或定位负担。旁白已锁定，任何改词/重配仍按既有授权范围处理；本次不擅自改音频，也不先指定一个更短的总时长。

**四、本次保留的成果**

- 文案已经回到“卷簧回卷＋手动制动锁止/释放”的原题，未再用尺头补偿顶替。
- 尺头折弯、铆接与壳口止挡的结构修正，以及有限姿态源几何证据有记录；本次没有证据推翻这些源事实。
- 银色卷簧与橙色尺带区分明确，连续展开、舞台和材质可延续。不是所有资产都要推倒重来。
- 原技术报告记录音视频全解码、同版CAD/网格对应等通过；本次现场确认文件身份和编码规格。技术通过不关闭上面两项内容问题。

**五、已经落实的漏审机制修复**

新增 `mechanical_video.action_alignment`，将冻结字幕中的明确动作声明与实际每帧运动比较：方向、变化量、保持状态、缺帧与非有限值均有检查。12项卷尺真实声明得到7项通过、5项阻断；失败内容就是第一节的五行，程序返回 BLOCKED，不靠人工印象打分。

v4的full-render/delivery门禁新增强制 `assets.action_alignment`，并绑定策略、运动、时间线与原题requirement；门禁会重读输入重算，不接受单独PASS标签。缺报告、旧输入或失败都会阻断。既有无出图场景前检继续负责几何/遮挡/连接，检查目标必须覆盖关键因果件。

新增动作检查7项测试，与场景/门禁集成8项、原制作门禁20项，本轮35项通过。卷尺四姿态真实 Blender 无出图复核已执行成功；先前通用六例无出图回归仍因另一个制作锁占用未执行，二者不混为一项通过记录。

这项代码能防止已声明动作的确定性错位，不能自动判断所有中文含义或代替听审。独立内容评审须检查声明是否完整、是否真的对应本题；不得删除失败声明或放宽阈值来“做绿”。

**六、影片处置与下一出口**

当前V7内容复核结论为REWORK；不是已修复视频，也不因这份报告生成就自动变为通过。生产者需在独占新版本修正开头/结尾事件时间，并验证锁止/释放视角的小样；既有V7、原音频、源机构与问题修复计数保留。只有新局部证据和同版终片复核通过才能关闭问题，不能再让用户先发现这两类错误。

本次未修改正在制作会话的共享导演记录，避免回退其新状态；本报告及机器可读缺陷单作为补充评审证据同步给制作项目。责任人为Director路由到Visual/Editor，旧问题计数由既有台账继承，不另起一套修复历史。
